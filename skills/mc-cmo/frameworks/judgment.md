# 判断框架

mc-cmo 在**轻过**和**深度介入**中使用此框架做出判断。**直通**不加载此文件。
（介入深度是流动判断，不是固定档位——见 SKILL.md「第 1 步」。）

---

## 快速检查清单（轻过使用）

轻过路径执行以下 3 项检查，任一项触发则升级为深度介入：

### 1. 品牌定位存在？
- 检查当前 campaign 的 `brand.md` 或 `memory/` 下的 `brand-memory.md`
- **存在** → 通过
- **不存在 + 用户请求的是内容/渠道/投放类技能** → 升级为深度介入
- **不存在 + 用户请求的是品牌/调研/竞品类技能** → 通过（这些技能本身就是在建立基础）

### 2. 风险等级？
- **低风险**（纯分析、信息查询、竞品监控）→ 通过
- **中风险**（内容创作、渠道选择）→ 通过，但附带 CMO 建议
- **高风险**（预算分配、投放策略、品牌定位变更）→ 升级为深度介入

风险分类：
| 低风险 | 中风险 | 高风险 |
|--------|--------|--------|
| mc-compete | mc-content | mc-campaign（含预算） |
| mc-monitor | mc-copy | mc-automation（触发型工作流） |
| mc-research | mc-aigc | 品牌定位变更 |
| mc-insight | mc-kol | 全链路编排 |
| mc-report | mc-seo / mc-geo | 预算 > 10万 的投放 |
| mc-review | mc-community | |
| | mc-livestream | |
| | mc-storyteller | |
| | mc-dtc | |

### 3. 信息完整？
- 用户的请求是否包含执行技能所需的最低信息？
- **完整** → 通过
- **缺少关键信息** → mc-cmo 用 CMO 语气追问（不是机械式表单）

## 完整判断流程（深度介入使用）

深度介入按以下 4 步执行：

### Step A: 意图拆解
- 用户真正想要什么？（表面需求 vs 深层需求）
- 这是一次性任务还是系列工作的一部分？
- 是否有隐含的上下文没说出来？

### Step B: 前置条件检查
- 品牌定位是否到位？
- 目标人群是否清晰？
- 是否有足够的数据/调研支撑接下来的决策？
- 是否有竞品分析？
- 渠道选择是否有依据？
- **常见需要质疑的场景（势能—买量颗粒度错配）**：处于单品验证期或新品牌冷启动期，尚未跑通种子人群转化与基础复购，却要求直接采买泛品类大词、全站泛人群包或头部品牌式品宣硬广。必须拦截并要求退回长尾痛点词与种子人群验证。
- **常见需要质疑的场景（负面冲动发声）**：针对未经核实或低转发的单条投诉 / 流言，要求立即"发公开声明辟谣"或"发律师函警告网友"。必须先经 `mc-diagnose` 负面→危机三级前置分流门禁判定 Tier 1/2/3，未命中升格信号时默认不公开回应，提醒一次逆火风险；用户坚持发事实澄清声明时，只能经 `mc-review` 7 项否决检视后起草发布，向普通消费者 / 网友发空头律师函威胁不予执行。
- **常见需要质疑的场景（无脑堆激励 / 阶段错配）**：对尚未形成购买意图的冷人群直接要求上签到积分、首屏满减弹窗与任务裂变。必须提醒一次“冷流量缺认知共识而非缺优惠，硬上行为激励只会洗出羊毛党”，建议先过 `mc-retain` / `mc-community` 行为阶段五问门禁，早期走 5 认知杠杆与减 Cons 摩擦，进入准备/行动期再切行为强化。

缺失的前置条件按重要性排序，向用户建议补全路径。

### Step C: 风险评估
- 这个决策的可逆性如何？（文案可以改，品牌定位改了影响全局）
- 涉及的资源投入量？（写篇文案 vs 启动全链路 campaign）
- 失败的代价？（一篇文案没效果 vs 10 万预算打水漂）
- **高危烧钱项（势能—买量颗粒度错配）**：冷启动/单品期越级投放泛品类大词或全站泛人群包（替行业头部交学费、无自然承接导致流量漏损），属于头号高危烧钱项，必须在路由前显式预警并建议锁死 L1 颗粒度。
- **高危放大项（逆火效应）**：对低量噪音发官方声明或向普通消费者发律师函，会把几百人可见的负面放大成全网事件，且不可逆；路由前显式预警，先私信闭环与暗中盯盘。

### Step D: 策略建议
基于 A/B/C 的分析，给出：
1. **推荐路径**：应该先做什么、再做什么、最后做什么
2. **理由**：为什么这个顺序最优
3. **风险提示**：如果跳过某些步骤，可能的后果
4. **预期产出**：每个步骤会产出什么，对后续有什么帮助

## cmo_context 输出格式

判断完成后，mc-cmo 在内部从判断阶段传给路由/执行阶段的上下文笔记格式：

<!-- CMO Context -->
**判断**：{一句话描述判断结论}
**建议**：{给技能的执行建议，1-2 句话}
**用户阶段**：{new/building/partner} — {该阶段的沟通要求}
<!-- /CMO Context -->

轻过的 cmo_context 尽量简短（1-2 行），深度介入的可以更详细（3-5 行）。
